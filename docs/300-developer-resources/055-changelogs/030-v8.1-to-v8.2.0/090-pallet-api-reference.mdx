Every structural API change between Polymesh chain **v8.1.3** and **v8.2.0**. It complements the narrative pages in the [v8.1.3 → v8.2.0 changelog](./010-overview.mdx). This reference was produced by comparing the v8.1.3 metadata of the live networks with the v8.2.0 metadata snapshots.

**Scope:**

- `transaction_version` is unchanged at `8`. Existing signing code needs no update, apart from the [new transaction extension](#transaction-extensions) for signers that hard-code the list.
- **Mainnet** gains two pallets, `WorkerModules` (60) and `ConfidentialAssets` (70). **Testnet** and **Develop** gain `WorkerModules`, and their existing `ConfidentialAssets` pallet changes in ways that are **not backwards compatible**.
- In every other pallet, everything is appended, so existing call, event and error indices are unchanged. Nothing is removed or renamed outside `ConfidentialAssets`.
- `pallet-precompiles` adds nothing to metadata. Precompile changes are in [Precompile Changes](./050-precompile-changes.mdx).

All proofs must come from DART v1.0.0, so every proof-carrying call needs new client code on Testnet, whether or not its argument type changed.

The added calls:

| Call                        | Arguments                                                                                                                              | Origin                  |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| `set_required_claim`        | `role: RoleKind`, `claim: Claim`, `trusted_issuers: BoundedVec<IdentityId>`                                                            | Root                    |
| `remove_required_claim`     | `role: RoleKind`                                                                                                                       | Root                    |
| `distribute_encryption_key` | `proof: KeyDistributionProof`                                                                                                          | Signed, `Auditor` claim |
| `update_asset_keys`         | `asset_id: u32`, `mediators: BoundedBTreeMap<AccountPublicKey, EncryptionPublicKey>`, `auditors: BoundedBTreeSet<EncryptionPublicKey>` | Asset issuer            |
| `set_asset_frozen`          | `asset_id: u32`, `frozen: bool`                                                                                                        | Asset issuer or Root    |

`RoleKind` is `AssetCreator`, `Auditor` or `Mediator`. `FreezeOrigin` is `Issuer` or `Root`.

| 48    | `NoKeyRecipients`            | `distribute_encryption_key` names no recipients                        |
| 49    | `TooManySharedKeyRecipients` | It names more than `MaxSharedKeyRecipients`                            |

| 51    | `AssetIsFrozen`              | A new settlement names a frozen asset                                  |

| 53    | `AssetIdOverflow`            | No more confidential asset ids are available                           |
| 54    | `TooManyProofs`              | A registration or proof batch exceeds its limit                        |

### Constants

| Constant                        | Value                   | Change                      |
| ------------------------------- | ----------------------- | --------------------------- |
| `MaxFeeAccountCurveTreeRootAge` | 14,400,000 ms (4 hours) | Was 172,800,000 ms (2 days) |
| `MaxRelayerCommission`          | 10 POLYX                | Added                       |
| `MaxSharedKeyRecipients`        | 5                       | Added                       |
| `MaxTrustedClaimIssuers`        | 2                       | Added                       |

Other limits are unchanged and identical on all three networks: at most 2 auditors and 2 mediators per asset, 10 legs per settlement, 10 proofs per batch, and root ages of 24 hours (assets) and 2 days (accounts).

### Storage

| Item                           | Shape                                                        | Change                                               |
| ------------------------------ | ------------------------------------------------------------ | ---------------------------------------------------- |
| `RequiredClaims`               | `RoleKind → RequiredClaim`                                   | Added                                                |
| `SharedKeyRecipients`          | `EncryptionPublicKey → BoundedBTreeSet<EncryptionPublicKey>` | Added                                                |
| `AssetFrozen`                  | `u32 → FreezeOrigin`                                         | Added                                                |
| `LegMediators`                 | `(SettlementRef, u8) → LegMediatorKeys`                      | Added                                                |
| `CachedDartParametersVersion`  | `ProtocolVersion`                                            | Added                                                |
| `RelayerSubmitExtensionMarker` | `()`                                                         | Added (transient, used by the transaction extension) |
| `Keys`                         | `u32 → AssetKeys`                                            | Value type changed (Testnet)                         |
| `FeeAccountRegistrations`      |                                                              | Removed (Testnet)                                    |

After finalization, a settlement keeps only its `SettlementState` entry. Its legs, memo, affirmation status, counters and `LegMediators` entries are removed.

### Runtime API

`ConfidentialAssetsApi::relayer_submit_batched_fee_info(batch: BatchedProofs) → RelayerSubmitBatchedFeeInfo { weight, fee }` returns the dispatch weight, including transaction extensions, and the full transaction fee of a `relayer_submit_batched_proofs` transaction for the batch.

## WorkerModules

Pallet index **60**. New on every network. All calls require Root. See [Worker Modules and Node Changes](./030-worker-modules.mdx).

### Calls

| Index | Call                             | Arguments                                                           |
| ----- | -------------------------------- | ------------------------------------------------------------------- |
| 0     | `register_protocol`              | `protocol_id: ProtocolId`, `metadata: ProtocolMetadata`             |
| 1     | `upload_protocol_module_code`    | `protocol: Protocol`, `code: BoundedVec<u8>`, `module_version: u32` |
| 2     | `upload_protocol_module_context` | `protocol: Protocol`, `context: BoundedVec<u8>`                     |
| 3     | `upload_protocol_module_config`  | `config: ProtocolModuleConfig`                                      |

### Events

| Event                           | Fields                                                                                        |
| ------------------------------- | --------------------------------------------------------------------------------------------- |
| `ProtocolRegistered`            | `protocol_id: ProtocolId`, `metadata: ProtocolMetadata`                                       |
| `ProtocolModuleCodeUploaded`    | `protocol: Protocol`, `code: BoundedVec<u8>`, `code_hash: BackendCodeHash`                    |
| `ProtocolModuleContextUploaded` | `protocol: Protocol`, `context: BoundedVec<u8>`, `context_hash: BackendContextHash`           |
| `ProtocolModuleConfigUploaded`  | `protocol: Protocol`, `config: ProtocolModuleConfig`, `config_hash: ProtocolModuleConfigHash` |

The code and context events carry the full uploaded bytes, up to several MiB.

### Errors

`ProtocolAlreadyRegistered`, `ProtocolNotRegistered`, `InvalidProtocolMetadata`, `ProtocolModuleCodeAlreadyExists`, `ProtocolModuleContextAlreadyExists`, `ProtocolModuleConfigAlreadyExists`, `ModuleCodeMissing`, `ModuleContextMissing`.

### Storage

| Item                 | Shape                                                         |
| -------------------- | ------------------------------------------------------------- |
| `Metadata`           | `ProtocolId → ProtocolMetadata`                               |
| `ProtocolConfigHash` | `Protocol → ProtocolModuleConfigHash` (the active config)     |
| `ProtocolConfig`     | `(Protocol, ProtocolModuleConfigHash) → ProtocolModuleConfig` |
| `ProtocolCode`       | `(Protocol, BackendCodeHash) → BoundedVec<u8>`                |
| `ProtocolContext`    | `(Protocol, BackendContextHash) → BoundedVec<u8>`             |

Limits are set in the runtime: module code up to 3 MiB, context up to 2 MiB, and up to 8 modules per configuration.

## Transaction extensions

`CheckRelayerSubmitBatchedProofs` is added after `CheckMetadataHash` and before `SetOrigin`, on every runtime. Its explicit and implicit data are `()`, so it adds no bytes to the extrinsic or the signed payload. See [Other Runtime Changes](./060-other-runtime-changes.mdx#new-transaction-extension).

## Runtime APIs

`ConfidentialAssetsApi` is new, with one method, [`relayer_submit_batched_fee_info`](#runtime-api). No other runtime API changes its version or signature.

The NFT transfer report behind `NFTApi` and the settlement report APIs now returns every applicable ownership error, rather than only the first. See [NFT Freezing](./040-nft-freezing.mdx#nft-transfer-reports-return-every-error).

## Behaviour changes without a signature change

| Call                                                                                                           | Change                                                                     |
| -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `Nft::controller_transfer`, `Nft::controller_transfer_to`                                                      | Unfreeze the NFTs they take, emitting `NFTsFrozenStatusUpdated` first      |
| `Nft::transfer_nft`, `Nft::redeem_nft`, `Settlement::*` affirm and execute, `Portfolio::move_portfolio_funds`  | Refuse NFTs frozen for the sender                                          |
| `MultiSig::remove_multisig_signers`, `remove_multisig_signers_via_admin`                                       | Outdate pending authorizations for the removed keys                        |
| `ExternalAgents::remove_agent`, `abdicate`                                                                     | Record an authorization cutoff for the removed agent                       |
| `Identity::remove_authorization`                                                                               | Accepts outdated authorizations                                            |
| `Settlement` affirmation counts                                                                                | Count a leg on both sides when the holders include its sender and receiver |
| Settlement NFT transfers                                                                                       | Fail if the receiving portfolio does not exist                             |
| `Portfolio::accept_portfolio_custody`                                                                          | Fails if the portfolio does not exist                                      |
| `Asset::set_asset_metadata`, `set_asset_metadata_details`                                                      | Refuse to lock an empty value                                              |
| Committee voting                                                                                               | A motion needs at least one vote; removed members lose all their votes     |
| `Validators::remove_permissioned_validator`                                                                    | Chills the identity's validating stashes                                   |
| Relayer subsidies                                                                                              | `Relayer` calls are self-paid before the subsidy allowance is checked      |
| `Asset::redeem`, `controller_transfer`, `controller_transfer_to`, `CapitalDistribution::claim`, `push_benefit` | Declare worst-case weight and refund the difference                        |

See [Other Runtime Changes](./060-other-runtime-changes.mdx) for each.
